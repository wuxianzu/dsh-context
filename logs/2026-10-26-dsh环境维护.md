# 2026-10-26 · DSH 环境维护与网络排查

**结论**:完成一次宿主升级后的插件与配置核对,修复了被重置的配置,打通 GitHub 工具链并建立归档仓库;同时把一次无线掉线问题定位到驱动层,进入观察期。

## 背景
宿主升级到 0.2.1-rc.3 后,检查第三方插件与配置是否完好;顺带处理长期的无线网卡间歇掉线。

## 过程
1. **升级核对**:逐项检查插件版本、激活列表与补丁配置,确认无丢失;一个第三方悬浮球插件的新版本已把此前两处本地补丁吸收进上游,本地补丁正式作废。
2. **配置恢复**:发现配置在一次启动失败后被应用自动重置(应用会保留时间戳备份),从备份恢复全部条目。
3. **GitHub 工具链**:配置细粒度访问令牌,凭据仅写入系统环境变量、不经过对话;验证读、写、提交三条链路均可用。
4. **归档仓库**:建立「脱敏归档」仓库,定下 `logs/ decisions/ handoff/ notes/` 四个目录与三条写入规则。
5. **无线掉线排查**:按顺序验证信号与信道(正常)→ 关闭系统与 USB 省电 → 清理同驱动的旧版本包(驱动层报错随之消失)→ 更换 USB 端口 → 关闭 802.11ax → 尝试 USB 降速模式(驱动不支持,已回滚)。系统报告给出的断开原因是「驱动主动断开」。

## 结论与教训
- 第三方插件 × 宿主升级是主要故障来源,升级前后都要备份与核对。
- 应用在启动失败时会重置配置并保留备份,恢复只需拷回。
- USB 无线网卡的掉线排查有固定顺序,系统自带报告能区分“驱动断开 / AP 断开 / 省电挂起”。
- 长会话需要外部记忆:小体量的交接笔记 + 按需检索的日志,比把历史全部重读更实用。
